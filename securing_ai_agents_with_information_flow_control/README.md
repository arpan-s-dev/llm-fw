# Securing AI Agents with Information-Flow Control

Implementation of [Securing AI Agents with Information-Flow Control](https://arxiv.org/abs/2505.23643v2) (Costa, Köpf, Kolluri, Paverd, Russinovich, Salem, Tople, Wutschitz, Zanella-Béguelin, 2025).

This is **Fides**: a planner that tracks confidentiality and integrity labels through the agent loop and **deterministically** allows or aborts tool calls. The LLM proposes actions; the policy engine decides.

## What this implements

- §4.1 lattices (integrity {T ⊑ U}, readers powerset, product lattice)
- Algorithms 2–3 (modular loop + basic planner) and 5–6 (taint-tracking)
- Algorithm 7 / §5.1 Fides HIDE and EXPAND
- §4.3 policies **P-T** (trusted action) and **P-F** (permitted flow)
- A three-tool agent (`read_file`, `search_web`, `send_email`) that reproduces the §1 indirect prompt-injection example

The LLM is an uninterpreted function M (§3). The demo uses a **scripted** model that follows a visible injection, so the firewall is model-independent and needs no API key.

## Threat model (smallest viable)

Trusted: system prompt, tool wrappers, policy engine, LLMs-as-configuration.  
Adversary: tampers with tool *results* (web pages, email bodies) and observes egress (sent mail).  
The LLM is **not** a security boundary.

Expected:

| Planner | Policy | Attack (email attacker) | Benign (email manager) |
|---------|--------|-------------------------|------------------------|
| Basic (Alg 3) | none | succeeds | no |
| Basic + taint (Alg 5–6) | P-T | **denied** | no |
| Basic + taint | P-F or P-T | **denied** | no |
| Fides HIDE (Alg 7) | P-F or P-T | payload never visible | **yes** |
